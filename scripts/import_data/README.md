# 講演資料からサイト用JSONへの変換

Python 3.9以上で動作します。PDFとExcelを手作業でJSONに転記する代わりに、このツールで照合・変換します。

## 最初の準備

kf77フォルダで実行してください。

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r scripts/import_data/requirements.txt
```

## ファイルを選ぶ画面

macOSでは、このフォルダの `start.command` をダブルクリックすると画面が開きます。プロジェクトの仮想環境・Codex同梱環境・通常のPythonの順に、必要なライブラリがある環境を探します。起動したターミナルを閉じると終了します。起動済みなら下記URLを直接開いてください。

コマンドで起動する場合：

```sh
.venv/bin/python scripts/import_data/web.py
```

ブラウザーで http://127.0.0.1:8765/ を開き、シフトPDF・参加登録Excel・講演題目Excelを選び、「JSONに変換して更新」を押します。次回からは同じ画面に新しい3資料を選ぶだけです。終了は起動したターミナルで Ctrl+C。ポートを変更する場合は `--port 8766` を付けます。

画面はこのパソコン上で動作します。GitHub Pagesは静的サイトのため、このPython画面は公開サイトには設置できません。資料は外部へ送信せず、一時ファイルは変換後に削除します。ファイル合計25MBまで対応します。

成功すると `data/talks.json`、`data/schedule.json`、`data/config.json` の開催日時を更新します。会場・SNS・運営情報など他の設定は保持します。画面からの実行ではNode.jsが見つかれば `dist/` も再生成します。通常のNode.jsに加え、Codexの同梱Node.jsも自動検出します。自動検出できない場合は `npm run build` を実行してください。Gitへのpushや本番公開は行いません。

## 対応する資料の形式

- 参加登録Excel：最初の行が現在のGoogleフォームの列名。氏名・氏名フリガナ・英語表記・所属・専門分野を読みます。「共通ID」は重複回答の判定にだけ使い、日時が新しい回答を採用します。同じIDで別名、同時刻で異なる回答があれば停止します。
- 講演題目Excel：データのあるシートは一つ。A列=氏名、B列=所属、C列=題目、D列=概要。見出しなし、または先頭が「氏名」「講演者」「講演者名」の見出し行に対応します。タイトル・概要・所属はこの資料を優先します。所属は「研究科」「学府」の直後で `affiliation` と `department` に分割し、残りの専攻・コース名は削りません。
- シフトPDF：文字情報と罫線を持つPDF。表の上に `11月21日 10:00～17:00` のような見出し、先頭行は `区分 / 10時 / 11時 / …`、時間区分行は `0–20 / 20–40 / 40–60` など。表座長・裏座長・受付は登壇枠に含めません。複数ページに対応しますが、日ごとの表には日付と時間の見出しが必要です。

画像だけのPDFや別レイアウトは対応外です。読めないセルを推測で埋めることはせず、エラーとして停止します。資料の形式を変更する場合は `converter.py` の読み取り処理も調整してください。

## IDと整合性

- 公開講演IDは `speaker-` + 空白を除去した参加登録の氏名。例：`speaker-安藤靖`。
- 同じ講演の複数回登壇は同じ `talkId` を使います。各枠の `speaker` も講演一覧と同じ表記になります。
- 照合時は空白・改行・全半角・ひらがな/カタカナを正規化します。「あんどうやすし」はフリガナとの一致から「安藤靖」に対応します。曖昧な類似文字検索は行いません。
- 現在は一人一題目を前提にします。同じ講演者が複数題目を持つ場合はエラーとします。氏名変更時はIDも変わるため、既存リンクの引き継ぎを別途検討してください。
- 座談会はタイトルを「座談会」とし、既存描画に対応する非講演枠の `type: "break"` で登録します。架空の講演者や講演IDは付けません。PDFの結合セルと明記された開始・終了時刻を照合し、12:00〜12:40を一枠として扱います。
- 未登録の講演ID、氏名不一致、重複ID、時間の欠落・重複・逆転、登壇枠のない題目があれば停止します。開催年は既存 `config.json` の日時から取得します。
- 題目のない参加者は講演一覧に追加せず、照合レポートの `registrationOnly` に記録します。運営名簿は自動変更しません。

## バックアップと照合レポート

更新前の3つのJSONと照合レポートは `.local/imports/日時-識別子/` に保存します。レポートには元ファイル名・SHA256・元資料の行/列・氏名照合の結果が入り、メールアドレスや内部共通IDは含みません。`.local/` はGit管理・静的ビルドのコピー対象外です。入力資料自体もリポジトリに保存しません。

全データを検証してから3ファイルを更新します。通常の書き込み失敗時には元のJSONへ復元します。ただし、3ファイルの差し替え途中の停電等は完全には防げないため、その場合はバックアップから復元してください。複数の変換プロセスを同時起動しないでください。

## コマンドで実行する場合

```sh
.venv/bin/python scripts/import_data/converter.py \
  --shift '/path/to/シフト.pdf' \
  --registration '/path/to/参加登録.xlsx' \
  --titles '/path/to/講演題目.xlsx'
```

`--check` は書き込まず検証だけを実行します。`--year 2027` で年を明示できます。`--output /path/to/data` で別の場所に出力できます。`--config` はベースとなる設定ファイル、`--report-dir` はバックアップ・レポートの保存先です。CLIはHTMLの再生成を行わないため、続けて `npm run build` を実行します。

## テスト

```sh
.venv/bin/python -m unittest discover -s scripts/import_data -v
```

元の3資料を保管したフォルダを `KF77_SOURCE_DIR` 環境変数に指定すると、今回の資料に対する統合テスト（13講演・51登壇枠・3座談会、結合枠、ID一致、公開項目の限定）も実行します。通常のテストでは架空のデータを使い、サイト用JSONを変更しません。
